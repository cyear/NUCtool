# NUCtool(Changelog)

## [0.5.0] - 2026-7-26

> 全面重构版本: 仅保留 Windows、根治历史"未知原因"问题、依赖全面更新、界面重做。
> 配置文件(`fan_config.json` / `beta.config`)与自动更新通道完全兼容, 可直接升级。

#### 💥 重大变更
- **仅保留 Windows 支持**, 移除全部 Linux 代码、配置与 CI 构建
  - Linux 用户请使用更早版本
- **硬件访问架构重写**: 所有 WMI/EC 操作收敛到单一 `hw-worker` 工作线程
  - 整个进程只建立**一次** COM/WMI 连接, 所有请求经通道排队串行执行
  - 旧版在多个线程反复 `ApiFan::init()` 并发调用 WMI, 是 分析.md 中
    "数据偶现巨大负数"(#2)、"风扇异常反复自动恢复"(#1)的主要根源
  - COM 安全初始化时序确定, 不再与其它线程竞争
  - 本机不受支持时进入降级模式: 界面正常打开、数据显示为空, 而不是直接闪退
- **全部 Tauri 命令异步化**: 旧版同步命令在主线程执行,
  `set_tdp` 内约 2 秒的写入间隔会直接冻结界面(分析.md #3 "界面卡死"), 现已根治
- 移除从未显示的 splashscreen 窗口(少一个常驻 WebView, 降低内存占用)

#### 🐛 修复 — 崩溃类(release 为 `panic=abort`, 以下旧版均直接闪退)
- 点击"加载配置"时配置文件缺失或损坏 → 闪退(现返回错误提示)
- 任意一次 WMI 调用失败 → 闪退(底层全链 `unwrap`; 现返回错误值并记录日志)
- 风扇曲线中两个点温度相同 → 插值除零崩溃(现排序去重)
- 更新弹窗 release body 为空 → 闪退(现空文本降级)
- 亚克力窗口特效应用失败 → 闪退(现打印警告继续运行)
- `beta.config` 内容带换行/空格 → 启动失败(现 trim 后解析, 异常时按默认值)
- 自启动状态查询失败 → 初始化中断(现忽略并继续)

#### 🐛 修复 — 逻辑类
- **温度超出曲线末端时风扇回落 0%**(修改过的配置文件可触发, 高温停转隐患;
  现保持末点转速)
- 温度读取异常时控制循环不休眠, 空转打满一个 CPU 核心(现休眠 2 秒重试)
- 停止控制用分离的"2 秒后复位"线程, 与快速重新启动存在竞态
  (现由控制线程退出时自行复位, 时序确定)
- 转速推送线程每次页面加载都新建一个, 反复刷新会泄漏线程(现全局仅一个)
- 控制启动时转速缓存初始为 `[0,0]`, 首个目标恰为 0% 时不会写入(现初始为无效值)
- 转速低字节未做掩码, 高位脏数据会污染拼接结果(现高低字节均 `& 0xFF`)
- `get_tdp` 返回顺序的文档注释与实现相反(已修正)
- 托盘退出改为**等风扇复位完成后**再退出进程(旧版为"睡 1 秒再复位", 存在未复位即退出的风险)

#### 🐛 修复 — 前端类
- `tdp.js` 调用 `get_rgb` 缺 `await`, 拿到的是 Promise 而非数据
- `set_rgb` 传参格式与后端不匹配(缺 `rgb` 包装), 调用必然失败
- 把数值写入 `<span>.value`(span 无此属性), 彩色模式关闭后滑条状态错乱
- 自启动场景直接连点"加载配置"和"启动", 配置未加载完就开始控制(现等待加载成功)
- 曲线图默认数据 66 个点对 15 个刻度(现一致)
- 顶层 `await` 与各命令调用均无错误处理(现统一 try/catch, 失败可感知)

#### ✨ 新特性
- **单实例限制**: 重复启动时唤起已有窗口(两个实例同时控制 EC 会互相干扰)
- 主界面新增运行状态指示(未运行 / 控制运行中), 启动/停止按钮状态化
- TDP 页写入过程有"写入中"反馈, 完成后自动回读
- 保存配置有"已保存 ✓"反馈
- UAC 提权被取消时干净退出(旧版为报错崩溃)

#### 🎨 界面重构
- 统一暗色玻璃设计系统(`src/assets/app.css`), 与窗口亚克力效果匹配;
  两个页面风格一致, 移除全部内联样式与三个零散 CSS 文件
- 主界面改为 2×2 卡片布局: CPU/GPU 曲线(可拖动) + 实时转速 + 实时温度
- 系列配色经色觉无障碍(CVD)与对比度校验: CPU 蓝 `#3987e5` / GPU 橙 `#d95926`
- 图表统一暗色主题: 细网格、稀疏刻度、悬停提示、双系列图例
- 调试页表单化: 带单位的数字输入框、原生开关、滑条; 保持零框架零构建

#### 🏗️ 工程结构
| 旧 | 新 |
|---|---|
| `plug/struct_set.rs`(ApiFan) | `hw/registers.rs` + `hw/device.rs` + `hw/mod.rs` |
| `plug/fan.rs` | `fan_control.rs` + `commands.rs` |
| `plug/tdp.rs` | `commands.rs` |
| `plug/config.rs` | `config.rs` |
| `plug/setup.rs` | `setup.rs` |
| `win_plug/wmi.rs` | `hw/wmi.rs` |
| `win_plug/permissions.rs` | `admin.rs` |
| `linux_plug/*`、`tauri.linux.conf.json` | 删除 |
| `b.css` / `styles.css` / `tdp.css` | `assets/app.css` |

- 寄存器命令改为类型安全的 u64 编码(读 `0x0000_0100_0000_0000|reg`、写 `(值<<16)|reg`),
  附与旧版字符串常量**逐一等价**的单元测试; WMI 传参方式保持与旧版一致
- 平台配置合并入 `tauri.conf.json`; capabilities 精简为最小权限集
- CI 精简为单一 windows-latest 任务; `package.json` 清理无用依赖
- 新增纯逻辑单元测试: 曲线插值(含新旧算法逐点一致性对照)、寄存器编码;
  硬件在环测试改为 `cargo test -- --test-threads=1`(需真机)
